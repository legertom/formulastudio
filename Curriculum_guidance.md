# Teaching Coding to Beginners & Children: Core Priorities

## 1. Cognitive Load Management
The single biggest mistake in beginner curricula is introducing too many new concepts simultaneously. Each step should ideally introduce **one** new idea, and that idea should build directly on something already mastered. If a learner has to hold more than 2-3 unfamiliar things in their head at once, they'll disengage.

## 2. Immediate, Visible Results
Every exercise should produce something the learner can **see and verify**. Abstract explanations fail beginners. If they type something and see the output change, they understand. If they type something and have to trust that "it'll matter later," they lose motivation.

## 3. Scaffolded Complexity
- **Start with the simplest possible working example** — not a simplified explanation of a complex one
- Add complexity in small, deliberate increments
- Each new step should feel like a natural "what if I wanted to..." question
- Never jump from "basic" to "intermediate" — fill every rung of the ladder

## 4. Pattern Recognition Over Memorization
Beginners don't need to memorize syntax. They need to **recognize patterns**. Show the same structure 3-4 times in slightly different contexts before expecting independent application. The progression should be: see it, trace it, modify it, write it.

## 5. Error as Learning, Not Failure
Design exercises where learners will encounter common mistakes **on purpose**, in a safe context. "What happens if you forget the closing parenthesis?" is more powerful than "always remember to close your parentheses."

## 6. Concrete Before Abstract
Never start with terminology or definitions. Start with a concrete task: "Make this cell show a name." Only after they've done it successfully do you name the concept ("that's called a string"). Vocabulary follows experience, not the reverse.

## 7. Motivating Context
Every exercise should answer "why would I care?" A formula that calculates something meaningful (even if trivial) beats a technically superior example that feels academic. Real-world scenarios — even silly ones — anchor learning.

## 8. Frequent Wins, Short Feedback Loops
Chapters should be broken into small steps where the learner succeeds often. A 20-step chapter where you only see results at step 20 is demoralizing. A 20-step chapter where you get a small "it works!" moment every 2-3 steps builds confidence.

---

## Common Red Flags in Beginner Curricula

These are the patterns to watch for when reviewing chapters:

- **Concept stacking** — introducing nesting, new functions, and new data types in the same step
- **Big leaps** — step N is easy, step N+1 requires knowledge that wasn't explicitly taught
- **Wall-of-text explanations** — trying to explain complexity instead of decomposing it
- **Assuming transfer** — expecting learners to apply a pattern from chapter 3 without a reminder
- **Front-loading theory** — explaining what something *is* before showing what it *does*
